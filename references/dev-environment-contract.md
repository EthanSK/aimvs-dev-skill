# Developer environment contract

Read before any AIMVS local dev-environment, dev-stack, emulator, or fixture operation.

- Stack 0's shared emulator data belongs to Ethan's main VS Code environment. Every nonzero dev stack must use its own isolated Firebase, Storage, MinIO, and Download Assets Worker backend; never point it at stack 0's backend or mutate shared data for an agent test. Never delete, clear, replace, anonymize, rename, or mark removed any pre-existing shared-emulator document to manufacture an empty or recovery state. Never restart the shared emulators from a worktree export until its source and representative collection counts have been verified against the currently owned full dataset.
- Before manually stopping or restarting any AIMVS Firebase emulator backend, export and verify its current data once. Use `npm run export-emulator-data` only for stack 0's shared backend. For every nonzero stack, stop its native writers first, then use the guarded `npm run isolated-backend -- stop --dev-stack-index=N` command so its private data is exported and its private containers stop cleanly. Do not run a periodic background exporter outside stack 0.
- If I tell you to use the Firestore emulator from Node/Admin SDK scripts, use the real standalone API project id `ai-music-video-studio-staging`, not the Firebase CLI alias `staging`; the emulator stores separate namespaces per project id, and using the alias patches the wrong data. `firebase` CLI commands may still use `--project staging` when that command expects the alias. Never add a one-shot migration, rebuild, repair, or backfill script—or a `package.json` command that invokes one—to any repository path, even temporarily or untracked. Create it only in a task-owned temporary directory outside the repository, execute and verify it with the required authorization, then delete it before handoff; retain tooling only when Ethan explicitly asks for a reusable permanent command.
- Stack 0 is my main VS Code environment. Agents must never start, stop, restart, restore, or use stack 0 for their own tests unless I explicitly ask for that exact stack 0 action; read-only port and log inspection is allowed.
- Manual browser tests and dev-stack runs are opt-in only: never run them automatically, not even as end-of-task verification — only when I explicitly ask for one in the current task. When I do ask, use the project skill `$aimvs-dev` for every AIMVS local browser test or dev-stack run; every agent-run test must use a free nonzero stack index with `--dev-stack-index=N`, even when testing source from the main checkout.
